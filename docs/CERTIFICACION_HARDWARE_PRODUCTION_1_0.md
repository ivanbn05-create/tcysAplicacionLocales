# Certificación hardware Production 1.0

Estado: protocolo preparado, **sin pruebas físicas ejecutadas**. Exclusivo laboratorio; no usar Arboledas, Santa Anita ni otra sucursal operativa. Rama codex/production-1.0-catalogo-promociones-dev.2; VERSION 1.0.0-dev.2 al redactar. Autoridad: docs/autoridad/ESPECIFICACION_PRODUCTION_1_0_LOS_TOCAYOS.md.

## Entorno y criterio común

Congelar SHA completo de Edge, Central y Pedidos, versión, hashes de artefactos y firmware/modelos. Usar una VM Windows Edge sacrificable, snapshot previo, Central de laboratorio con PostgreSQL y TLS/CA, una PC cliente, dos tabletas Android 8+ y dos impresoras térmicas de prueba en red privada. Central debe emitir identidad de sucursal lab y tarjeta de enrolamiento de un uso. No copiar bases, tarjetas, secretos o identidades de sucursales reales. El proxy HTTPS local y la CA se comprueban desde otra terminal; el verificador local no acredita ese tramo externo.

Preparar release Edge 1.x completa y firmada con wheelhouse CPython 3.13/win_amd64; registrar SHA-256 de ZIP, manifiesto, sumas, firma, bootstrap y trust store. Custodiar clave privada fuera de repositorio y VM Edge. No aprobar hardware con source-only o AllowUnverifiedDevelopmentTree. Para actualización preparar por separado un dev.10 auténtico en otra VM/snapshot y un verificador de firma externo cuya huella se fijó por canal independiente.

Antes/después de cada caso capturar sin secretos: VERSION, commit del manifiesto, salud, aprovisionamiento, publicación y ACK, UUID/conteos de tickets, precios capturados, outbox, cola, integridad SQLite, tarea de respaldo, ACL, firewall y SHA-256 de .env. Dos personas observan: operador y verificador del papel/datos. Una fila pasa sólo cuando estado durable y observación humana coinciden. Código de salida cero, /salud/ o socket TCP alcanzable no prueban aceptación operativa.

Estado de cada fila: P pasó, F falló, B bloqueado por prerequisito, NE no ejecutado. Mantener NE hasta observar el hardware. Un F/B/NE mantiene abierto el gate.

## Entradas verificadas en el código

Todos los comandos siguientes se ejecutan en PowerShell elevado de VM lab con rutas absolutas reales y valores ficticios. La tarjeta de enrolamiento y CA quedan en carpeta privada fuera de Git. El nombre de firma se toma del artefacto generado; el ejemplo es ilustrativo.

    & .\instalar-universal-desde-release.ps1 -ArchivePath C:\cert-lab\release\Edge-1.0.0-dev.2.zip -ManifestPath C:\cert-lab\release\Edge-1.0.0-dev.2.manifest.json -ChecksumPath C:\cert-lab\release\Edge-1.0.0-dev.2.sha256 -SignaturePath C:\cert-lab\release\Edge-1.0.0-dev.2.signature.json -TrustStorePath C:\cert-lab\custodia\release-trust.json -ExpectedVersion 1.0.0-dev.2 -InstallationRoot C:\cert-lab\Edge -CentralUrl https://central-lab.example.invalid -EnrollmentCardPath C:\cert-lab\privado\tarjeta.json -CentralCaBundle C:\cert-lab\custodia\central-ca.pem -AllowedHosts localhost,127.0.0.1,edge-lab.example.invalid -Https

Este bootstrap verifica cuatro artefactos antes de ejecutar código del ZIP, exige wheelhouse y tarjeta privada. Https exige además proxy local de laboratorio; no usar AllowInsecureHttpLan para este gate.

Para dev.10 → 1.x, en el árbol de desarrollo del actualizador usar los parámetros exactos de actualizar-laboratorio-desde-release.ps1. Ejecutar primero con PrepareOnly y después sin él. La transición 0.x→1.x exige SignaturePath, TrustStorePath, SignatureVerifierPath y TrustedVerifierSha256. El verificador debe provenir fuera de la instalación dev.10 y su SHA se comprueba por canal independiente. Usar InstallationRoot de la VM dev.10 y WorkspaceRoot externo. Conservar staging y árbol anterior. El script revierte sólo si detecta fallo de aplicación/salud; hay que ensayarlo.

    & .\actualizar-laboratorio-desde-release.ps1 -ArchivePath C:\cert-lab\release\Edge-1.0.0-dev.2.zip -ManifestPath C:\cert-lab\release\Edge-1.0.0-dev.2.manifest.json -ChecksumPath C:\cert-lab\release\Edge-1.0.0-dev.2.sha256 -SignaturePath C:\cert-lab\release\Edge-1.0.0-dev.2.signature.json -TrustStorePath C:\cert-lab\custodia\release-trust.json -ExpectedVersion 1.0.0-dev.2 -InstallationRoot C:\cert-lab\Edge-dev10 -WorkspaceRoot C:\cert-lab\staging-update -SignatureVerifierPath C:\cert-lab\custodia\release_firma.ps1 -TrustedVerifierSha256 SHA256_VERIFICADO -PrepareOnly

No ejecutar la segunda pasada si PrepareOnly, firma, hash, snapshot o respaldo fallan. En la segunda pasada quitar solamente PrepareOnly.

Comprobaciones disponibles tras instalación o actualización:

    & C:\cert-lab\Edge\verificar-servicio-lan.ps1
    & C:\cert-lab\Edge\verificar-servicio-lan.ps1 -RunBackup -BackupTimeoutSeconds 600
    & C:\cert-lab\Edge\.venv\Scripts\python.exe C:\cert-lab\Edge\manage.py diagnosticar_impresoras --json

La tercera línea sondea sockets sin transmitir papel. Registrar su JSON redactado y cotejar IP/puerto autorizados antes de un ticket físico.

Para H03, fabricar únicamente en una rama/VM desechable una release negativa distinta, limpia, con VERSION propio y firma de laboratorio: inyectar un fallo determinista en el wrapper de actualización después del paso de migraciones, nunca en la candidata dev.2. Verificar que el ZIP negativo supera firma, PrepareOnly y conmutación; registrar el marcador justo antes del fallo y observar la restauración automática. Una segunda prueba puede fallar antes de migrar para separar ambos puntos. No distribuir esta release negativa. H03/H04/H17/H18 exigen snapshot y VM descartable. No usar Stop-Service como sustituto del crash: es una parada ordenada. El apagado brusco se registra desde el hipervisor sin improvisar sobre hardware de sucursal. Para H15 el repositorio sólo implementa respaldo consistente y restauración de comprobación interna en herramientas/respaldo_sqlite.py; no tiene comando público de restore integral. La restauración manual de un clon no cierra esa brecha. H17 exige recuperación durable del actualizador tras muerte del proceso: el `catch` actual no se ejecuta ante apagón. H18 exige copia externa verificable de SQLite y configuración, custodia de secretos y restauración en VM nueva; H14/H15 no la sustituyen.
